## 一、怎么发现这条规则的

最早是在 [③ 服务端看哪些字段](03-服务端看哪些字段.md) 里注意到 `DUv` 不能乱改：

```
com.coolapk.market2       → ✗ 全 0   （加一个字符就拒）
COM.COOLAPK.MARKET        → ✗ 全 0   （大写也拒）
com.coolapk.mark          → ✗ 全 0   （截断也拒）
random.package.xyz        → ✗ 全 0
```

当时只得出「`DUv` 精确匹配」这一个结论。
后来做 [⑩ 自己造 App 验证](10-自己造App验证.md) 时才发现更具体的形态：**它是一份白名单**。

## 三、三条关键推论

### 3.1 是「按具体 App」的白名单，不是按厂商

```
com.baidu.searchbox   → ★ 36 字符    （百度）
com.baidu.BaiduMap    → ✗ 全 0        （百度地图）
```

**同一家公司的两个 App，一个通过一个拒绝。**

⇒ 名单粒度是「单个包名」，不是「厂商前缀」。

### 3.2 不是「包名 ↔ apiKey 配对校验」

`com.zhihu.android` 用**酷安的 apiKey** 照样成功：

```
DUv = com.zhihu.android
75c = 11e7b222083a4b732b4b14811f6fc05995a01415eb   ← 酷安的值
→ ★ 88 字符
```

如果服务端校验配对，这里应该失败。

### 3.3 apiKey 完全不参与签发门控

同一批包名，第二次把 `75c` **整个删掉**再跑：

```
包名                        75c=酷安key    75c=删除
com.coolapk.market         ★ 36          ★ 36
com.zhihu.android          ★ 88          ★ 88
com.sina.weibo             ★ 88          ★ 88
com.ss.android.ugc.aweme   ★ 36          ★ 36
com.xingin.xhs             ★ 36          ★ 36
com.tencent.mm             ✗ 全0         ✗ 全0
com.taobao.taobao          ✗ 全0         ✗ 全0
com.jingdong.app.mall      ✗ 全0         ✗ 全0
```

**两列完全一致。**

**⇒ Python 侧和 App 侧结论一致，说明报文构造方法可靠。**

## 五、为什么 36 / 88 两种长度

观察分布：

| 长度 | 包名 |
|---|---|
| 36 字符 | 酷安、抖音、小红书、网易云音乐、B站、快手、百度、搜狐新闻 |
| 88 字符 | 知乎、微博 |

88 字符的结构：

```
DU8N1bbZfcNSfbmsBFOhsJslrOSOR3dL6eg5                     ← 前 36
RFU4TjFiYlpmY05TZmJtc0JGT2hzSnNsck9TT1IzZEw2ZWc1c2h1     ← 后 52，base64
  ↓ base64 解码
DU8N1bbZfcNSfbmsBFOhsJslrOSOR3dL6eg5shu                 ← 前 36 + "shu"
```

**⇒ 88 = 36 + base64(36 + "shu")，是个自校验结构。**

**⇒ 长度由服务端按客户配置决定，不是版本差异。** 同一个服务端、同一套报文格式，
只换 `DUv` 就能拿到两种长度，所以它必然是**账户级配置**。

## 六、一个没想通的问题

既然 apiKey 完全不影响签发结果，那「接入」这个商业流程到底给了客户什么？

目前只能推测，服务端后台至少配置了三样东西：

1. **包名**（决定是否放行）
2. **ID 格式**（36 还是 88，有没有自校验段）
3. 可能还有 `store` 字段之类的归属标识

而 `apiKey`（42 字符那个）纯粹是 SDK 本地的格式校验，
`cn.shuzilm.config.json` 里的 RSA 公钥则完全不参与 `init()`。

⇒ **换句话说：商务流程的产出主要是「把你的包名加进白名单」，而不是发一把钥匙。**

## 七、这对使用意味着什么

| 场景 | 可行性 |
|---|---|
| 用白名单里的包名做测试 | ✅ 可以，随时能拿号 |
| 用自己的包名 | ❌ 拿不到，返回 36 个 0 |
| 学 wx/taobao 的包名 | ❌ 也不在名单里 |
| 「接入」数字联盟 | 需要商务流程，产出是被加进白名单 |
