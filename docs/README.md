| `06-DUID-普适性.md` | DUID 跨设备 / 跨环境的表现 |

### 核心结论摘要

```
服务端按 (sfOo, foO, 2cO) 三元组查表：
  ① 命中            → 返回该记录关联的 DUID（与其余 73 字段无关）
  ② 未命中 + body 完整 → 新建记录，签发【新 DUID】
  ③ 未命中 + body 精简 → 返回全 0

★ 最小可用 body = 8 字段: DUv + 3mS + 75c + 2cO + sfOo + foO + AAA + BBB
```

### 三条硬经验

```
① maps 重定向 —— 不要挂钩 read()
   ✗ 挂钩 read() 过滤 maps 内容 → read 极高频 → 目标 App ANR
   ✓ 在 open/openat 层重定向 → 现场生成滤过副本，返回副本 fd

② hex 转换必须加条件
   ✗ 对每条 SSL 记录都转 hex → 千万次 JS 操作 → ANR
   ✓ 只对「像 HTTP」或「够大」的记录转

③ NativePointer 与 Java byte[] 要分开处理
   ✗ new Uint8Array(nativePtr) → 静默返回空 → 数据全丢
   ✓ nativePtr.readByteArray(n) / new Uint8Array(javaArray)
```

## 05-mis-history/ — mIS 专题（**含已被推翻的结论**）

> ⚠️ **重要提示**
>
> 本目录内的早期结论——特别是「`mIS` 是唯一钥匙 / 判据种子」——**已被实验推翻**。
> 保留的目的是记录**推理过程**与**错误是怎么产生的**。
>
> **当前正确结论请以 `docs/02-anchor/` 为准。**

### 错误是怎么产生的（值得引以为戒）

```
早期做法：逐字段扫描 87 个字段，看哪个改了会让结果变化
问题：    扫描时【一直保持 mIS 为真值】
后果：    那个真值足以命中记录 → 遮蔽了其它所有字段的作用
误判：    得出「mIS 是唯一钥匙」

修正方法：先把 mIS 随机化，再逐字段扫描
修正结果：真正的锚点是 (sfOo, foO, 2cO)；mIS 换成任意合法值都不影响
```

**教训**：变体测试时，**不要让待测字段携带能独立命中目标的真值**。
