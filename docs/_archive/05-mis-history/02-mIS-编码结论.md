# `mIS` 编码逆向 —— 静态方法的结果（实验 2）

> 日期：2026-10-03
> 目标：解出 `mIS` 的编码，拿到它的「明文层」，从而找构造来源。

---

## 一、收集到的全部 `mIS` 样本（6 个）

```
'-\1c21`/\]d]`./10X[^c]b\X-`Xb_0/-_Xa'
'9j9g>jg:63>>kh96>k63<g:j3<6lkghggi3i'
'BrBrGppp?uGEtsBpG<?tE?Cq<G?<tCqspp<s'
'JQyPE~yLLEKIMMKHL{~}OHQJEy}P}E{HI|~|'
'TMP"OU"Q#JM#P"VRNQ"JQVTNJ~VUNS#~UVJ!'
"W[\Y''(X%S%%U'W&ZP)UXYU(PW[P*WSY&XP&"
```

长度都是 **36**。字符集 **72 种**：
```
!"#%&'()*-./012369:<>?BCEGHIJKLMNOPQRSTUVWXYZ[\]^_`abcdghijklpqrstuy{|}~
```

---

## 二、★ 一条决定性的观察：**不是 XOR**

```
在某个样本里：   T -> (      （0x54 -> 0x28）
                \ -> &      （0x5C -> 0x26）
因为 T XOR \ = 0x08，若编码是「明文 XOR 固定密钥」，不可能出现这种组合
（XOR 是双射：同一个密钥只能产生一个结果）

⇒ 排除「固定 XOR 密钥」。
```

**这与 body 的加密（`zlib XOR pool`）不同** —— `mIS` 用的是**另一种机制**。

---

## 三、静态求解的三种假设都失败

`mis_keystream.py` 的做法：假设明文 ∈ 某个字符集，对每个位置求「能让所有样本
都成立的密钥字节」，看是否唯一。

| 假设的明文集合 | 唯一确定的位置 | 结论 |
|---|---|---|
| 标准 base64（64 种） | **2 / 36** | ✗ |
| url-safe base64（64 种） | **4 / 36** | ✗ |
| 任意可打印 ASCII（95 种） | **0 / 36** | ✗ |

**⇒ `mIS` 不是「明文 XOR 位置密钥」。**

候选的其它机制（都未验证）：

```
① 先做逐字节变换（如 +N / 取反 / 按位重排），再查表
② 密钥流与明文相关（类似流密码 / CBC）
③ 完全不同的构造：把二进制直接映射到 0x21~0x7E（如 base85 的变体）
④ 它是【哈希输出经二次编码】—— 那就根本没有「明文层」可还原
```

---

## 四、同时确认的（这些是有价值的确定结论）

```
· 排除「固定 XOR 密钥」（§二）
· 排除「单表代换」—— 同一个字符在不同位置映射到不同输出：
    样本内位 27 出现两次 'P'，而位 8/10/12/… 的 'P' 输出与它不同
    同一个样本里 '3' 出现在位 9/19/24/34，输出各不相同
· 36 个位置【每一位都在变】⇒ 整串都是「每批重算」的数据，没有固定魔数/版本段
  （若有固定段，跨样本该位应恒定）
· 字符集 72 种 > base64 的 64 ⇒ 不是纯 base64
```

## 五、★ 结论与下一步

### 5.1 结论

```
mIS 的编码【静态解不出来】—— 试过 base64 变体、单表代换、位置密钥流，全失败。
它的机制与 body 的「zlib XOR pool」不同，是另一套。
```

### 5.2 ⇒ 唯一可行的路：**动态取值**

```
思路：不猜编码，直接看它生成时的【输入】。

在 libdu.so 里钩这几个点（按可行性排序）：
  ① 字符串生成：mIS 是 36 字符，大概率由某个「编码函数」产出；
     钩 native 的 snprintf/strcpy/ memcpy 之类，在结果里搜 36 字符模式
  ② JSON 拼装：body 的字段名（"mIS"）与值一定在内存里相邻，
     钩字符串拼接点，往前追「值是怎么算出来的」
  ③ 若走 JNI 回 Java 取设备信息：钩 JNIEnv 的函数表（仓库已有 JNIEnv 偏移表的资料）

另外可以先用一个【极低成本的实验】排除一类可能：
  · 在设备上改一个设备特征（如改机型 R3d），重启酷安，
    再抓一次 mIS ——
      · mIS 变了  -> 它确实由设备特征构造（值得继续追）
      · mIS 没变  -> 它与设备特征无关（可能是随机/时间/服务端下发）
  这个实验只要 1 次设备操作 + 1 次抓取，性价比最高。
```

**本仓库已有**：`libdu.so` 的 JNIEnv 偏移表、native 方法表、
pool 常量表（5 个）、以及 `cap_zlib.js`（可复用做动态抓取）。

## 七、教训

```
① 我按「body 是 zlib XOR pool」的既有印象去套 mIS，先试了 XOR ——
   但一个反例（T 与 \ 映射到不同的两个字符）就能排除它。
   找反例比试假设更快。

② 「静态解不出」本身是有价值的结论：它把候选机制压缩到
   「流密码/哈希后编码/非线性变换」，并且明确了下一步只能走动态。
   失败要写清楚「试过什么、为什么不行」，否则下一轮会重复。
```
