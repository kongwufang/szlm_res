# hook 目标选择：三次翻车记录

## 一、这次犯的错

`real_java2.js` 挂了 `java.io.OutputStream.write([B)` 和 `write([B,int,int)`。

**结果：所有应用被卡崩。**

原因：`OutputStream.write` 是 **Java IO 的基类方法，所有流写入都经过它**。
频率极高 —— TLS 握手的每个记录、每个 HTTP 响应体、文件读写，全部走这里。
挂了之后每次写入都要进 frida 的 JS 回调，开销直接压垮 ART。

日志里也看得很清楚：抓到的第一批数据全是 **X.509 证书**
（`308202d2a003020102...`），那是 TLS 握手时逐条写入的证书链 —— 
**说明这个 hook 点在最底层，什么都拦。**

这是第三次犯同类错误了。

---

## 二、三次翻车对比

| # | 挂了什么 | 后果 |
|---|---|---|
| 1 | `memcpy` / `strcpy` / `strncpy` / `strcat` | 酷安 5 秒 ANR |
| 2 | `okhttp3.RequestBody.writeTo`（含自递归 bug） | 所有应用被卡退 |
| 3 | `java.io.OutputStream.write` | 所有应用被卡崩 |

**共同点：都是「所有调用都经过」的底层方法。**

而我之前已经明确记录过这条红线：

```
禁止: memcpy/strcpy/strncpy/strcat（5 秒 ANR）
      ioctl/write、deflate/gzwrite
      Memory.scanSync 遍历全 rw 区间
```

`OutputStream.write` 的性质和它们完全一样，我却还是挂了。

---

## 三、根因分析：为什么会挑错

我在找「能拿到 body 明文」的点，思路是：
「body 最终要写进流里，所以挂流的 write 就能拿到」。

**这个推理在逻辑上没错，但忽略了频率这个决定性约束。**

正确的判断标准应该是：

```
这个函数在单位时间内会被调用多少次？
  - 每秒几次      -> 安全
  - 每秒几十次    -> 勉强
  - 每秒上千次    -> 必崩
```

`OutputStream.write` 是最后一种。

---

## 四、正确的目标：`javax.crypto.Cipher.doFinal`

**应该挂的是加密的终点，而不是 IO 的起点。**

```js
const Cipher = Java.use('javax.crypto.Cipher');
const df = Cipher.doFinal.overload('[B');
df.implementation = function (input) {
    const out = df.call(this, input);   // 用 .call，不重入
    // input  = 加密前的明文（压缩后的 JSON）
    // out    = 密文
    // 两个都拿到
    return out;
};
```

**为什么这个点对**：

| 维度 | `OutputStream.write` | `Cipher.doFinal` |
|---|---|---|
| 调用频率 | 每秒上千次 | **每秒几次** |
| 覆盖范围 | 所有 IO | **只有加密操作** |
| 拿到的数据 | 密文（还要自己解） | **明文 + 密文都有** |
| 副作用风险 | 极高 | 低 |

**关键优势：`doFinal` 的入参就是明文。** 不需要请求 key 了——
它直接把「压缩后的 JSON 明文」交到手上。

而这恰好是我一直缺的东西：**请求体的明文**。

## 五、修正后的实施纪律

**动手前必须先回答三个问题：**

1. **调用频率估计**：这个函数每秒会被调多少次？
2. **覆盖范围**：它是不是某个大类的必经之路？
3. **失败代价**：挂了之后能不能安全卸载，还是直接崩系统？

**任一问题答案不利，就不挂。**

**低压验证流程**：

```
1. 先只挂一个点，用 print 记录调用次数（不读参数）
2. 观察 30 秒，确认进程稳定
3. 再逐步加上读参数、读返回值
4. 任何一步出现卡顿立即撤回
```

**我之前的做法是「一次挂满」，这是错的。**

## 七、下次继续时的第一步

```js
// 只挂这一个点，先验证稳定性和频率
const Cipher = Java.use('javax.crypto.Cipher');
Cipher.doFinal.overload('[B').implementation = function (input) {
    const out = Cipher.doFinal.overload('[B').call(this, input);
    try {
        if (out.length >= 200) send('[doFinal] in=' + input.length + ' out=' + out.length);
    } catch (e) {}
    return out;
};
```

用 `attach_all.py 120 real_cipher.js`（不带 `--no-clear`，先看稳定性）。
