## 一、★★★ 突破过程（四道防线，逐个击破）

### 防线 1：基于「文件名 + 端口」检测 frida

```
现象：默认 frida-server（文件名 frida-server、端口 27042）
      -> attach 报 "unable to connect to remote frida-server: closed"
对策：★ 复制成 /data/local/tmp/fs + 用端口 31337
      -> attach 不再被立即拒绝
```

### 防线 2：frida-server 权限不足 → spawn 不可用

```
现象：spawn 报 "need Gadget to attach on jailed Android"
原因：之前用 `nohup ... &` 在 `su -c` 里启动，丢了 root 权限
对策：★ 用 `setsid /data/local/tmp/fs -l 0.0.0.0:31337 &`
      -> uid=0000（root），spawn 成功
```

### 防线 3：`prctl(0x53564D41)` = "SVMA" 自定义反调试点

```
现象：抓到 prctl(1398164801, 0)，1398164801 = 0x53564D41
对策：★ Interceptor.replace(prctl)，命中该魔数时返回 0
      ★ 其余调用【原样透传】（v1 全返回 0 会导致 app ANR）
```

### 防线 4：★★★ `tgkill` 发送 SIGTRAP（决定性的一击）

```
现象：logcat 反复出现
        F libc: Fatal signal 5 (SIGTRAP), code -6 (SI_TKILL)
        #03 pc ... /memfd:frida-agent-32.so (deleted)
      说明：反调试用 tgkill/tkill 发 SIGTRAP 打死 frida-agent
      而普通的 kill() 钩子【拦不到 tgkill】

对策：★ 挂钩并拦截 tgkill / tkill / pthread_kill / raise 里的
        SIGTRAP(5) 与 SIGABRT(6)
      ★ 挂钩 read()，把 /proc/self/maps 内容里含 frida/gum/gadget 的行过滤掉
```

## 七、教训（四道防线的启示）

```
① 反调试往往是【多层】的，要一层层剥离：
   名字/端口检测 -> 权限不足 -> 自定义 prctl -> SIGTRAP 信号

② 「信号」是很容易被忽略的一层。
   我一直只挂 kill()，忽略了 tgkill/tkill 才是真正杀 frida 的手段。
   线索来自 logcat 的一行："Fatal signal 5 (SIGTRAP), code -6 (SI_TKILL)"

③ 拦截要【透传】而不是【全拦】。
   v1 把所有 prctl 都返回 0 -> app ANR；
   v2 改成只拦魔数、其余透传 -> 正常。

④ 用 setsid 而不是 nohup 保持 root（nohup 在 su -c 里会丢权限）。
```
