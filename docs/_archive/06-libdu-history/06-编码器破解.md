## 一、★★★ 解密算法（完整还原）

### 1.1 汇编原文（解密例程 @0x0DA3A4）

```asm
0DA3A4  adrp  x9, #0x14000
0DA3A8  mov   x1, x0
0DA3AC  mov   x8, xzr                ; i = 0
0DA3B0  add   x9, x9, #0x4cd         ; ★ 密文地址 = 0x14000 + 0x4cd = 0x144CD
0DA3B4  mov   w10, #-0x71            ; ★ 密钥 A = 0x8F（奇数位用）
0DA3B8  add   x11, x11, #0x10        ; 目的缓冲尾
0DA3BC  stur  x12, [x29, #-8]
0DA3C0  mov   w12, #-0x6e            ; ★ 密钥 B = 0x92（偶数位用）
0DA3C4  stp   xzr, xzr, [sp]
0DA3C8  strh  wzr, [sp, #0x10]
0DA3CC  ldrb  w13, [x9, x8]          ; ← 循环开始：读密文[i]
0DA3D0  tst   x8, #1                 ; 位置奇偶
0DA3D4  csel  w14, w12, w10, eq      ; 偶→B(0x92)  奇→A(0x8F)
0DA3D8  add   x8, x8, #1
0DA3DC  eor   w13, w13, w14          ; ★ XOR 解密
0DA3E0  cmp   x8, #0x11              ; ★ 长度 17
0DA3E4  strb  w13, [x11, #-1]!       ; ★ 倒序写入（指针先减再写）
0DA3E8  b.ne  #0xda3cc
```

### 1.2 用 Python 表述

```python
def decode(data, addr, kA, kB, length):
    """kA = 奇数位密钥, kB = 偶数位密钥；结果需反转"""
    enc = data[addr:addr + length]
    raw = bytes(enc[t] ^ (kB if t % 2 == 0 else kA) for t in range(length))
    return raw[::-1]          # ★ strb 是从尾部往前写，所以要反转
```

**验证（与已知明文逐字节对照通过）：**
```
@0x144CD kA=0x8F kB=0x92 L=17  ->  'nemud.player_uuid'   ★ 全可打印
@0x144F5 kA=0x91 kB=0x93 L=19  ->  'persist.nox.wifimac' ★ 全可打印
@0x1443D kA=0x8F kB=0x91 L=17  ->  'ro.microvirt.hmac'   ★ 全可打印
@0x14410 kA=0x8F kB=0x92 L=17  ->  'sys.usb.vserialno'   ★ 全可打印
```

### 1.3 为什么之前失败

```
我最初用「+1 顺序」去解 @0x144F5，得到 'persist.nox.wifimac' —— 全可打印
（因为长度 19 是奇数，反转后再反转恰好自抵消）
但对偶数长度的串就会失败 —— 这就是「有的解得出、有的解不出」的原因。

⇒ 教训：写入方向（顺序 vs 倒序）必须从汇编里读出来，不能靠试。
```

## 四、★ 扫描结果：33 个密文地址，13 个严格解出

```
密文地址 33 个（引用 0x14000 页的 adrp+add）
严格模式解出 13 个，其中全可打印 11 个

★ 另外发现一个高价值字符串：
   0x014470 kA=0x91 kB=0x93 len=19  ->  '/storage/emulated/0'

这也解释了「余下的乱码」：它们是【用别的密钥对加密的】——
本库每个字符串的密钥对【各自独立】，不是全局常量。
```

### 4.1 各调用点的密钥对分布

```
kA/kB 组合（已见到 8 组）：
  0x8F/0x92   0x8F/0x91   0x91/0x93   0x8D/0x91
  0x89/0x8B   0x89/0x8D   0x8E/0x8B   0x83/0x85
⇒ 密钥对是【逐字符串指定】的（写在调用点前面的 mov 里）
   这就是为什么「同一套密钥通吃」必然失败。
```

### 4.2 仍未解出的（需要进一步处理）

## 八、教训

```
① 反汇编里读出来的事实，不要靠试。
   「写入方向」这件事，我试了两轮（顺序/倒序都试过），
   而它就在 `strb w13, [x11, #-1]!` 这一个指令里写着：
   #-1! = pre-decrement = 倒序。一条指令能省两轮。

② 一个未解出的异常值 = 一条线索，不是噪音。
   长度 19 的串（奇数）反转自抵消，所以能"碰巧"解出；
   长度 17 的（奇数）也一样；但偶数长度会暴露方向问题。
   —— 当时应该立刻用「偶数长度的串」去交叉验证方向。

③ .rodata 只有 1484 字节这个数字本身就是最强线索。
   我把它当成「加壳」就停了，应该继续问：
   「1484 字节里能装多少字符串？显然装不下全部 —— 那其余的从哪来？」
   答案就是：加密 + 运行时解密。

④ 静态分析的价值：一旦破解，不受设备/时机限制，可反复分析。
   前面 15 种动态方法都是在绕「库加载时机」这个不可控因素。
```
