# 数盟上报端点探测报告（B 路线）

目标：用纯自研代码构造上报请求，取回 DUID。
方法：以已复刻的协议直连 `auni.telecome.cn`，逐维度探测服务端要求。

---

## 一、结论先行

**协议复刻是完整的；卡点在服务端端点本身。**

`POST http://auni.telecome.cn/a/mdna/report` 对**任何**请求体、任何参数、任何请求头，从**本机和设备两端**都返回 `400 Bad Request`（响应体为空、无 `Allow` 头）。这不是参数问题，是端点整体拒绝。

---

## 二、排除矩阵（全部实测）

| 维度 | 尝试内容 | 结果 |
|---|---|---|
| 路径 | `/a/mdna/report`、`/a/mdna/report/`、`/a/report`、`/mdna/report`、`/`、`/robots.txt`、`/xyz-random-9999` | POST 全部 400 |
| HTTP 方法 | GET / POST / PUT / HEAD / DELETE / OPTIONS / PATCH | 只有 POST 得 400，GET/HEAD 走应用路由（404） |
| 请求头 | 无头 / 仅 UA / 酷安全套 `X-Sdk-*` / Origin+Referer+XFF / device_label | 全部 400 |
| Content-Type | `application/octet-stream` / `json` / `text/plain` / `x-www-form-urlencoded` / 不带 | 全部 400 |
| body 封装 | 14 种：4头+AES(gzip)、纯AES、纯gzip、纯JSON、长度前缀(BE/LE)、反序头、空、随机字节…… | 全部 400 |
| URL 参数 | 去掉 v/t/n/l、`v=0..100`、`t=m/a/d/1/2/w/s/android/ios`、p/r/h 全0/16位/64位/空/MD5(空) | 全部 400 |
| HTTP 版本 | HTTP/1.1、HTTP/2(h2 TLS)、HTTP/2(h2c) | 全部 400 |
| 来源 | 本机（家庭宽带）、设备本身（10.0.0.7，经 toybox nc） | 两端都 400 |

**关键判据**：`POST /robots.txt`、`POST /health`、`POST /xyz-random-9999` 也都是 400 —— 这些路径不可能有业务逻辑。**说明 400 是网关层面按方法整体拦截，与业务无关。**

## 四、旁证：域名现状

```
auni.telecome.cn  ->  阿里云 ALB (alb-27czf8vp82ngqn280w.cn-beijing.alb.aliyuncs.com)
                       GET  /                -> 200（空）
                       GET  /a/mdna/report   -> 404 page not found（Go 路由存在）
                       POST /a/mdna/report   -> 400（网关拦截）
auni.telecome.com ->  域名停放页（window.location.href="/lander"），无关
shuzilm.cn        ->  203.107.60.192，POST -> 405（数盟官网存活）
szlm.cn           ->  47.243.64.211，POST -> 404
```

`*.telecome.cn` 下只有 `auni` 能解析，其余全部 NXDOMAIN。结合「POST 一律 400」，**该上报端点很可能已停用或迁移**，残留的 ALB 规则对 POST 直接拒绝。

---

## 五、因此剩下的可能

1. **端点已迁移**：新地址写在 `libdu.so` 的加密字符串里（`strDec@0x1143bc` 运行时解密），静态搜不到。要拿到需在设备上 hook 那个解密函数。
2. **需要特定接入条件**：如专线、IP 白名单、或特定 TLS 客户端指纹。已排除 UA/Origin/XFF/HTTP2，但无法排除 ALB 自定义规则。
3. **`v=8.7` 协议已废弃**：服务端可能只接受新版协议，而新版参数结构已变。

---

## 六、给后续的建议

**优先级 1 —— 拿到真实请求的 URL**（唯一能确认端点与新参数的方式）
- 挂 `strDec@0x1143bc` 抓解密后的域名/URL 模板（该点已实测安全，不会触发反调试）
- 但注册请求发生在进程启动早期，等稳定再挂会错过；早期注入又会被反调试杀 —— 这是已知死结
- 唯一可行窗口：**设备 reboot 后，酷安首次冷启动的那几秒**，趁反调试尚未完全加载

**优先级 2 —— 在设备上抓包**
- 设备有 Magisk root，可跑 `tcpdump`
- 但需先有流量产生，而数盟在「已注册」状态下不联网

**优先级 3 —— 接受现状**
- 协议层已 100% 复刻并验证
- 若数盟端点确已废弃，则「纯自研代码获取新 DUID」在基础设施层面就不成立
