## 六、★★ 剩下三个真正的缺口

### 缺口 A：mIS 的 36 字节 XOR 密钥

```
已有：
  ✓ 算法结构：mIS = XOR(base64(27字节指纹), key)
  ✓ 字母表 = 标准 "A-Za-z0-9+/"（运行时实物）
  ✓ 编码函数 = libdu 偏移 0x0E123C（3 个调用者已挂钩）
  ✓ 字母表在内存的偏移 = 模块 + 0x1783E4
  ✓ 位 4 恒定 ⇒ 密钥固定（非随机）

缺的：
  ✗ key 的 36 个具体字节

怎么补（已备好）：
  · 在库加载窗口（清数据 + 走同意 → 库加载，已验证可复现）
    直接读 base + 0x1783E4 的 64 字节（只读一个地址，不会掉线）
  · 同时挂 0x0E123C 的钩子，读编码函数的输入/输出
  · 从调用点前的 `mov wN, #-imm` 直接读出 key 常量

前置：缺口 B（否则编码器不执行）
```

### 缺口 B：mIS 的触发条件（谁调用 `Main.init`）

```
已有：
  ✓ 两台设备的 SDK 状态都是「未就绪」：pkg="" / bu="" / q.w=0
  ✓ Main.init 0 次命中（我们把 Main 的所有方法都挂上了）
  ✓ 但 SDK 确实工作过：DUID 已签发、du.lock 存在、库会加载
  ✓ 库加载窗口可复现（清数据 + 走同意）

缺的：
  ✗ Coolapk 里【谁负责调用 Main.init】这一段代码

怎么补（已备好，只需更早的时机）：
  · 挂钩 java.lang.ClassLoader.loadClass
    → 当类名含 'cn.shuzilm' 时打印调用栈
  · 关键是要在【szlm 类加载之前】就把钩子装上
    ⇒ 用 frida.spawn + gating（D3 上已验证可行）
    ⇒ 或轮询 Java.enumerateLoadedClasses 直到出现第一个 szlm 类，
      立刻抓那一刻的调用栈
```

### 缺口 C：无 root 设备如何拿到 DUID（因 G2 才存在）

```
已有：
  ✓ 有 root 的路径（读 dna.xml / prefs）—— 三台设备验证通过

缺的：
  ✗ 无 root 的读取方式

候选（均未验证）：
  · Android 系统备份（Settings → 备份与恢复）
      → Coolapk 的 shared_prefs 是否被纳入备份
  · adb backup -f b.ab com.coolapk.market（需设备允许）
  · 厂商云同步（如小米/华为云）是否同步 app 数据
  · 与官方酷安共享 uid（需签名一致 —— 做不到）
  · 从 Coolapk 自身的"设备信息"界面读取（若它显示该 ID）
```

## 八、★ 一个需要澄清的问题

```
原始目标里有一句：「把设备指纹发上去把酷安申请的 id 拿下来」

现有证据表明：
  · 设备指纹（26+ 个字段）我们已经能构造（协议、字段、编码都清楚了）
  · 「酷安申请的 id」= DUID，已经能从设备读到（需 root）
  · 但服务端【不接受自造的 mIS】（自造值全 0）

⇒ 所以"把指纹发上去"这条路的前提是：
    要么 mIS 能本地算出来（缺口 A），
    要么抓一次真实请求（含 mIS）然后重放（已实现，样本 wire_m58_REQ_9）

★ 如果目标是「普通用户拿到一个可用的 ID」，那么：
   · 最实际的路径其实是【抓一次真实请求然后复用】
     —— 不需要算 mIS，也不需要 root
     —— 但需要能抓到那个请求（root 或 VPN/代理）
   · 或者【直接读 dna.xml】（需 root）

⇒ 建议先明确：目标是"构造请求"还是"拿一个可用 ID"？
   两者需要的缺口不同：
     构造请求 -> 缺口 A（密钥）+ B（触发）
     拿可用 ID -> 缺口 C（无 root 读取）
```
