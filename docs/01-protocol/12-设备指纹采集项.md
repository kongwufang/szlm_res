## 二、MD5 函数参数约定（实测修正）

```
0xe23c4  MD5 包装（22 处调用）
0xe1de4  MD5 实体
```

**实测参数布局**（与最初猜测不同）：

| 寄存器 | 含义 | 实测证据 |
|---|---|---|
| `x0` | **输出缓冲**（跨调用恒定，如 `0x7d76865a80`） | 22 次调用 x0 完全不变 |
| `x1` | **输入数据**（每次变化，位于栈区） | 读出的内容即 1.1–1.7 的各项指纹 |
| `x2` | 辅助指针 | — |
| 返回值 `r` | **字符串指针**（不是缓冲地址） | 输出需读 `r` 而非 `x0` |

**踩坑**：最初误把 `x0` 当输入，导致读到的全是输出缓冲的垃圾；且 `onLeave` 时 `x0` 缓冲尚未写入，
必须读**返回值**。未修正前抓到的输出值（`D067890C…`、`660252AE…`）因未与输入配对，**不可作为 `p` 的判定依据**。

## 三、report 函数实测参数

```
##### report #####
  a0 = 0x7d9b47ef60   指针数组（含 0x1f 填充可见于 a4）
  a1 = 0x27b6  (10166)
  a2 = 0x2
  a3 = 0x7d673ece40   全 0 缓冲
  a4 = 0x7d673ece85   反复的 0x1f
  a5 = 0x4
```

调用链（backtrace 实测）：
```
libdu+0x40cbc -> 0x3e35c -> 0x452d4 -> 0x11f420 -> 0x132148 -> 0x125ed0 -> libc
```
`0x40cbc` 是核心分发器，**不可 hook**（高频，会拖死数盟线程，实测封死后流程完全停摆）。

## 四、运行环境要点（避坑）

1. **DUID 双写**：`com.coolapk.market_dna.xml` + `coolapk_preferences_v7.xml`。
   清缓存测试必须两处同清，否则被回填、酷安走快路径、不触发上报流程。
2. **清 `coolapk_preferences_v7.xml` 会连带清掉「隐私协议已同意」状态**，
   导致酷安回到协议页、数盟不初始化（`libdu` 不加载）。
   → 采集时**不清缓存**，改用**主动调 `DUHelper.query`** 触发上报。
3. **frida 隐身必须常开**：拦截 `fopen/open/openat` 把 `/proc/self/maps`、`/proc/self/status`
   重定向到过滤副本（写 app 私有目录）。否则易盾探测到 frida，`libdu+0xc2638` 调 `kill()` 自杀。
4. **设备电量**：USB 供电慢于耗电，实测充电约 +1%/分钟（低电量涓流阶段更慢）。
   采集前须确认电量，低于 25% 不宜开测。
