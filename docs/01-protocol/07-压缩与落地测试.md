# 两项测试结果：zlib 明文钩子 + c001apk 落地

> 日期：2026-10-03 ｜ 主力设备：**D3 LineageOS GSI**（按你的提醒：性能好、成功率高）
>
> **结论：① zlib 钩子本身可用，但 mdna 始终不发；② 落地的键位置已定，但仍缺 `mIS` 种子。**

---

## 一、测试 ①：zlib 明文钩子（拿 body 明文，绕开抓包）

### 1.1 钩子本身装好了

`cap_zlib.js` 覆盖 `libz.so` / `libc.so` / `libdu.so` 的
`deflate` / `compress` / `compress2`，在**压缩前**把输入缓冲 dump 出来：

```
[D3_Z]     [ok] zlib 相关库挂了 5 个钩子
[D3_Z]     [ok] cap_zlib 装好 pid=14934（含 zlib 明文钩子）
```

判定逻辑：输入里出现 `{"` 且含 ≥3 个 body 特征字段（`DUv`/`mIS`/`3mS`/`2cO`/`AAA`/`BBB`）
才落盘并打印 `mIS` / `2cO`。

### 1.2 但一次都没触发

```
[D3_Z] [4] 汇总 attached=3 落盘=0
[D3_Z] [5] 解出 0 个明文 body
```

**两次尝试（删 dna 路径 / pm clear 路径）都是 0 命中。**

### 1.3 ★ 原因：不是钩子的问题，是 **mdna 根本没发**

```
钩子装在进程里（3~5 个进程都装上了），但 deflate 从未被调用
⇒ 没有任何 szlm body 被压缩过
⇒ mdna 请求没有发出
```

这与前面几轮的结论一致（`/a/` 请求在上报周期外不发）。

### 1.4 这次用的触发方式

**pm clear 路径**（首次登记）下的日志：

```
[3] pm clear（首次登记路径 —— 必发 mdna）
    Success
弹窗: 点 '同意协议并继续' @ (210,430)  [前台=com.coolapk.market]     ← 协议页点到了
弹窗: 点 '允许' @ (160,253)  [前台=com.coolapk.market]              ← 通知权限也点了
[ok] cap_zlib 装好 pid=18582
✓ attach com.coolapk.market:xg_vip_service pid=18582
…（共 5 个进程）
[4] 汇总 attached=5 落盘=0
```

**协议页与权限弹窗都处理对了，但 `mdna` 依然没发。**

### 1.5 说明什么

```
· 我之前推断「pm clear 后的冷启动必发 mdna」—— 【不成立】
· 删 dna.xml 触发的是别的路径（N_D2 那轮抓到过 daa），也不是 mdna
· mdna 的真实触发条件仍未确定，可能与「服务端下发的周期」有关
  （响应里有 itime=604800 = 7 天）
```

## 二、测试 ②：c001apk 落地

### 2.1 三台的安装情况（★ 与你之前的记录不同）

```
D1  68881797301726      com.example.c001apk.compose      ← 包名带 .compose
D2  10.0.0.7:5555       com.example.c001apk              ← 经典包名
D3  35P102BOBPG00LF     （未安装）
```

D2 上的版本：`c001apk_next-V1.0.1-debug`（versionCode 10001，targetSdk 34）

### 2.2 c001apk 自己的 prefs 状态

```
/data/data/com.example.c001apk/shared_prefs/
    WebViewChromiumPrefs.xml
    com.example.c001apk.xml        ← 只有 INSTALL_TIME
    settings.xml
    shuzilm_probe.xml              ← 探针的落盘
```

`shuzilm_probe.xml` 内容（**残留的探针结果**）：

```xml
<string name="probe_version">spoof-proc-1</string>
<string name="run">spoof-proc-1  spoofPkg=(真实包名)</string>
<string name="did"></string>                 ← 空
<string name="dna">(无 _dna.xml)</string>     ← 无
<string name="verdict">timeout</string>       ← 超时
```

**⇒ c001apk 上没有任何 DUID，探针当时是 `timeout`。**

### 2.3 ★ 落地的确切位置（已定）

```
官方酷安（com.coolapk.market）的 DUID 在两处：
  shared_prefs/com.coolapk.market_dna.xml          <device_id>
  shared_prefs/coolapk_preferences_v7.xml          <SHUZILM_DID>

⇒ c001apk 若对等实现，应写：
  shared_prefs/<自己的包名>_dna.xml                 <device_id>
  shared_prefs/c001apk_preferences_v7.xml           <SHUZILM_DID>
  或它自己的 preferences 里的同名键
```

### 2.4 ★ 但落地还缺一环：**`mIS` 种子**

```
要让 c001apk 拿到【服务端认的】DUID，请求必须带：
    mIS   —— 服务端登记过的精确值（改 1 字符就全 0）
    2cO   —— 纳秒部分逐纳秒精确
这两个种子：
  · 不在 prefs（33 个云控键 + 3790 个键名全扫过）
  · 不是 Java 字段名（80 个候选类扫过，无命中）
  · 只在 mdna 的 body 里 —— 而 mdna 现在发不出来
```

**⇒ 落地分成两种情形：**

| 情形 | 可行性 | 做法 |
|---|---|---|
| **c001apk 只要能读到 DUID 值**（不自己向服务端要） | **可行** | 从官方酷安的两处 prefs 读出来用（需 root 或共享 uid） |
| **c001apk 想自己向服务端要** | **仍不可行** | 需要 `mIS`/`2cO`，而这两者现在拿不到 |

## 三、这一轮真正的收获

```

   —— 工具就位，只等 mdna 发一次
② mdna 的触发条件被证伪了两个假设：
     「删 dna.xml 会发」     ✗
     「pm clear 冷启动会发」  ✗
③ 落地的键位置完全确定（dna.xml 的 device_id + prefs 的 SHUZILM_DID）
④ 卡点收敛成一句话：
     种子只在 mdna 的 body 里，而 mdna 只在服务端下发的周期到点时才发
```

## 四、下一步的三条路（按可行性）

### 路 A：等周期 / 触发周期（最被动但不费力）

```
响应里的 itime = 604800（7 天）。
若上报周期就是这个，那「让 mdna 发」= 等，或者把服务端记录的
「上次上报时间」弄掉（但那在服务端，做不到）。

更实际的做法：让 D3 保持已注册状态放一段时间，
每隔几小时用 zlib 钩子挂一次，撞到就抓到。
```

### 路 B：从 native 侧直接 dump 明文（不依赖 mdna 是否发）

```
既然 body = zlib.compress(JSON) XOR pool，而 mask/pool 是常量，
那就：找到 libdu.so 里【异或循环】的位置，钩它，
     入参是压缩后的字节，出参是密文；
     但明文 JSON 在更早一步 —— 需要钩到 JSON 构造点。

或者反向：钩 native 的 strlen/strstr 之类，在 mIS 字符串被构造时捕获。
```

### 路 C：先落地「读 DUID」这一半（对你的目标直接有用）

```
在已 root 的设备上：
  c001apk 读 /data/data/com.coolapk.market/shared_prefs/*_dna.xml 的 device_id
  或读 coolapk_preferences_v7.xml 的 SHUZILM_DID
即可拿到【这台设备的真 DUID】，可直接用于业务请求。

⇒ 这一半不依赖 mIS，可以马上做
```

## 六、教训

```
① 我把「pm clear 后必发 mdna」当成事实推了好几轮 —— 它被本轮证伪。
   以后关于「触发条件」的推断，都应该先做一次最小验证再往下依赖。

② zlib 钩子这条路是对的方向（不等网络、不等时序），
   只是现在缺「让 mdna 发一次」这个前提。

③ 落地的键位置很明确，但「落地能不能真起作用」取决于 mIS ——
   而 mIS 又回到 mdna。整个问题被这一个环节卡住。
```
