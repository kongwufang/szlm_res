## 一、★★ 交叉验证的直接结果（`dna.xml` 是明文可读的）

三台的 `shared_prefs/com.coolapk.market_dna.xml`：

```xml
<!-- D1 TK_Watch (68881797301726) -->
<string name="device_id">DUaVFlbAMrmH2Z57PEhm_N9EO4RoUdvNstg5</string>
<string name="device_label">6KYDnLSlcHZQV83Yq2P63w==</string>

<!-- D2 XTQ_Watch (10.0.0.7:5555) -->
<string name="device_id">DUFPnec5dST2pTeImYGBClyhOnoUecHYyWg9</string>
<string name="device_label">6KYDnLSlcHZQV83Yq2P63w==</string>

<!-- D3 LineageOS GSI (35P102BOBPG00LF) -->
（无 dna.xml —— 尚未注册成功）
```

### 1.1 两点确认

```
① DUID 逐设备不同
   DUFPnec5…（D2）≠ DUaVFlb…（D1）
   ⇒ 与之前记录一致

② ★ device_label 却【两台相同】：6KYDnLSlcHZQV83Yq2P63w==
   ⇒ 这修正了我在 GOAL_GAP_ANALYSIS §3.2 的一处推测 ——
     当时我以为 device_label 是「逐应用身份」，但两台不同设备拿到同一个值，
     说明它【不随设备变】，是应用身份（包名+签名）层面的值。
   ⇒ 与 c001apk 的 OrS6X9cNLr6g7a7YpyZy5A== 不同，也自洽（不同包名）
```

### 1.2 ★ 对目标的重要含义

```
DUID 就明文躺在 shared_prefs 里（XML，无需解密）。
⇒ 「手机装了酷安 → 取回它的 DUID」这件事，在已 root 的设备上**直接读文件即可**，
   不需要抓包、不需要重算算法。

剩下的问题只有：「普通用户设备（无 root）怎么办」——
  要么应用有读其它 app 私有目录的权限（不可能），
  要么走服务端（就回到 mIS / 2cO 种子那条路）。
```

## 三、★ 弹窗处理修的一个真 bug

D3（Android 13）首次运行会弹「允许酷安向您发送通知吗？」：

```
[38,232][282,274]  「允许」   cx=160 cy=253
[38,278][282,320]  「不允许」 cx=160 cy=299
```

**第一版选择逻辑点错了 —— 点了「不允许」**，原因是：

```
「不允许」【包含】「允许」这个子串
旧逻辑： if k in t  →  "允许" in "不允许" == True  → 命中
        再按 (rank, -y) 排序 → 「不允许」y 更大 → 反而排前面
```

**修法**（`dialog_killer.py`）：

```
① 先排除拒绝类： t in DENY_TEXTS / 含 DENY_TEXTS 子串 / 含「不」字 → 跳过
② 再匹配允许类，优先「始终允许」>「允许」>「同意」…
```

单元验证：

```
通知弹窗  -> (160, 253, '允许')        ✓ 没点「不允许」
权限弹窗  -> (160, 253, '始终允许')     ✓ 优先最宽松授权
无允许项  -> None                      ✓ 不乱点
```

## 四、抓包结果：仍然只拿到响应，没拿到请求

```
D2 本轮落盘 4 个文件，全是 HTTP 响应：
  p8042_RESP_1.bin  1900 字节  head=48 54 54 50 2f 31 2e 31 20 32 30 30  ("HTTP/1.1 200")
  p8042_RESP_2.bin  1840 字节  同上
  p8042_RESP_3.bin     0 字节
  p9378_RESP_1.bin   168 字节  同上

D1 / D3：0 个文件
```

**⇒ `SSL_read` 钩子正常，`SSL_write` 上没有任何 `/a/` 请求。**

### 4.1 一个必须解决的矛盾

```
· 删 dna.xml 之前，dna.xml 是【存在】的（三台的删除前清单里都列到了）
· 删掉后重启 → 按逻辑应该触发「重取 ID」并发出 mdna
· 但三台都没有任何 /a/ 请求
```

可能的原因（都未验证）：

```
① 上报有周期（itime=604800 = 7 天），删本地文件不足以强制立即上报
② 请求走的是【native 裸 socket】，而我的 sendto/sendmsg 钩子判据
   要求前 1500 字节里出现 "POST /a/" —— 若 szlm 用非标准格式或分片首包很短，会漏
③ 请求在 app 启动的极早期发出，而钩子是在 watcher 发现进程后才装上（有时序窗口）
```

### 4.2 下一步更该做的（比继续抓包更直接）

```
· dna.xml 已经明文给出 DUID ⇒ 交叉验证已完成，不需要抓到 mdna
· 真正还缺的是【mIS 与 2cO 两个种子的来源】
  → 但它们只出现在 mdna 的 body 里 ⇒ 还是得抓到 mdna
  → 或者：反射读出构造 mdna body 的那个 Java 状态对象（比抓网络稳）
```

## 八、教训

```
① 「点击时屏幕上是哪个 app」必须显式校验 ——
   本轮门拦下了 22+6 次误点，验证了你的判断。

② 文案匹配要防【子串包含】：「不允许」包含「允许」，
   这类错误在中文界面上很常见（「不同意」「不再提示」同理）。
   正确做法是先排除否定式，再匹配肯定式。

③ dna.xml 是明文 XML —— 这一点早该想到。
   「取 DUID」在我自己的（已 root）设备上根本不需要抓包，
   我去追网络上报追了好几轮。
```
