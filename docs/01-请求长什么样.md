## 端点

抓包得到的全部通信端点：

| 路径 | 用途 |
|---|---|
| `/a/mdna/report?v=8.7&t=m` | **取 ID** —— 首次注册时 `h=0` |
| `/a/adt/report` | 后续上报 |
| `/a/dcc2/request?v=2.0` | 请求 |
| `/a/dai/report?v=2.2` | 上报 |
| `/a/daa/report?v=1.1` | 上报 |

主机固定为 `auni.telecome.cn`。

另有**两条备用线路**（走别的域名，带 `appkey` 头）：

```
POST /anti_logs   →  Host: yumao.puata.info
POST /ra          →  Host: ccs.umeng.com      (Content-Encoding: xgzip)
```

两者的 body 前 10 字节相同（`2aeb393b33373531693d`）—— 未进一步分析，不影响主流程。

## URL 参数

```
?a/mdna/report?v=8.7&t=m&p=<32hex>&r=<32hex>&n=0&l=2&h=<32hex>
```

| 参数 | 含义 | 服务端是否校验 |
|---|---|---|
| `v` | 协议版本 | **✔ 唯一被校验的 URL 参数** |
| `t` | 类型（`m`） | ✗ |
| `p` | 见下 | ✗ |
| `r` | 随机 32 位 hex | ✗ |
| `n` | 计数 | ✗ |
| `l` | 等级 | ✗ |
| `h` | 见下 | ✗ |

**测法**：`p`/`r`/`n`/`l`/`h`/`t` 各测 6~8 种变体（随机值、全 0、删除、空、别的设备的值……），
**全部通过且响应逐字节相同**。只有 `v=0` 会返回 400。

## 两个可推导的参数

### `p`

```
p = MD5(packageName + "." + 后缀).upper()
```

酷安的值：

```
MD5("com.coolapk.market" + "." + "37be8a1ee106979a")
  = F9BD0FBDACFE80FCF34370FBCFEE1A98
```

那个 16 位后缀（`37be8a1ee106979a`）由 libdu 生成，**具体派生规则未解出**
（不依赖 android_id / serialno / 机型 / 厂商 / MAC —— 这些改动都不影响它）。

**但服务端不校验 `p`**，所以自研实现时可以把它当常量。

### `h`

```
h = MD5(DUID + "." + "889e0b01").upper()
```

- 首次注册（还没有 DUID 时）为 `"0"`
- 有 DUID 后是上面这个值

**服务端同样不校验 `h`** —— 甚至可以用**另一台设备**的 `h` 值，照样通过。

## 请求头

```
Content-Type: application/x-www-form-urlencoded
User-Agent: Dalvik/2.1.0 (Linux; U; Android 8.1; <设备型号> Build/<版本>)
Accept: */*
Accept-Encoding: identity
Host: auni.telecome.cn
```

**21 组请求头变体测试**（换 UA、删头、最小头集）—— **全部无影响**。

UA 保留真机格式只是为了稳妥，不是必需。

## 响应

```
HTTP/1.1 200 OK
Content-Type: application/octet-stream
Content-Length: 114
```

body 同样是加密的，解开后形如：

```json
{"err":"0","n_a":"DUaVFlbAMrmH2Z57PEhm_N9EO4RoUdvNstg5","nctl":"2",
 "ocdd":"","cdd":"DUaVFlbAMrmH2Z57PEhm_N9EO4RoUdvNstg5",
 "o_a":"","dlab":"…","denv":"0","isem":"1","itime":"604800"}
```

| 字段 | 含义 |
|---|---|
| `err` | `"0"` 正常 |
| `n_a` | **DUID** ← 主要关注这个 |
| `cdd` | 通常是 `n_a` 的同值 |
| `dlab` | base64 的一个 16 字节值 |
| `isem` | `"1"` 表示本次是注册 |

**三种失败形态是不同的东西：**

```
n_a = 真 DUID       成功
n_a = "0" × 36      值被判据否掉（字段不自洽）
n_a = ""            结构不合法（服务端没进业务逻辑）
```
