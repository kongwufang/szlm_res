## 三、实测结果

### 3.1 ★★ 重要发现：`cn.shuzilm.core.Main` 在 **544ms** 就加载了

```
✓✓✓ attach 成功 pid=4859
[ok] 类加载钩子: ClassLoader.loadClass(String), loadClass(String,boolean), Class.forName, BaseDexClassLoader.findClass

```

**⇒ 数盟的类在 app **启动早期**就加载，不是在注册时。**
**⇒ 要抓「谁加载了它」必须用 `frida.spawn + gating`，在 Java 虚拟机启动前就装钩子。**
**⇒ 而且——不需要点按钮！类加载与注册无关。**

## 四、结论（区分实测与推断）

**实测：**
- `cn.shuzilm.core.Main` 在 app 启动 ~544ms 加载，早于协议页交互
- `Java.choose('android.app.Activity')` 可用，能找到 MainActivity
- 从 Activity 拿 decorView 后 View 树遍历失败（只 3 行）
- S07 `pm clear` 后重注册，DUID 不变

**推断：**
- 缺口 B 的正确姿势是 `spawn + gating`（在 JVM 起来前装 loadClass 钩子），**与点按钮无关**
- performClick 失败与「frida 挂着时 adb input tap 失效」可能是同一类问题（UI 线程/事件分发受影响）
