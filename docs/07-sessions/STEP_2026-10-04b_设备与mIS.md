### 3.4 ★★★★ mIS 性质被否证（纯离线数值分析）

用 6 个 mIS 样本做差分分析（`mis_sparsity.py` / `mis_key_test.py`）：

```
① XTQ_Watch【同一设备】两次注册：
     mIS#1 = JQyPE~yLLEKIMMKHL{~}OHQJEy}P}E{HI|~|   (2cO 子秒 291441780)
     mIS#2 = BrBrGppp?uGEtsBpG<?tE?Cq<G?<tCqspp<s   (2cO 子秒 17322914)
     ⇒ 完全不同（36/36 字节都不同）

② 汉明距离：
     同设备两两 : 111 / 132 / 155 位（38% / 46% / 54%）
     跨设备平均 : 118 位（41%）
     随机基线   : 144 位（50%）
   ⇒ 【同设备的差异 与 跨设备的差异 相当】
   ⇒ mIS 每次注册都像是全新的随机值

③ ★ 决定性：逐位求「能让该位置所有样本都落回 base64url 的 delta」
     pos 5 : 可行 delta = 0 个
     pos 8 : 可行 delta = 0 个
   ⇒ 【不存在任何固定逐位 key】能把所有样本还原成 base64url
   ⇒ 「mIS = XOR(base64(27字节), 固定key)」【不成立】
```

**★ 与旧文档的冲突要如实记录：**
`GOAL_GAP_CLOSURE_AUDIT.md` 缺口 A 写的是「mIS = 逐位 XOR(base64(27字节指纹), key)，
缺口只差 key 的 36 字节」。**本轮数值分析否证了这个前提** ——
若 key 固定，则每个位置的 delta 必然存在；pos 5/8 处不存在 → **key 不是固定的**。

**⇒ 更可能的解释（推断，未证实）：**
- mIS 是**每次注册新生成的随机/半随机会话标识**
- 由**服务端记录**（mIS → DUID 的映射）
- 所以它**不能由客户端离线算出**

## 四、结论

**实测：**
- D4 的 IP 从 `.42` 变为 `.43`；D1 仍未上线
- D2 内存里有 8 处标准 base64 表
- app 空闲时编码器 `0x0E123C` / `0x0E115C` 零调用
- 双路抓包可用；抓到 **szlm appkey `5a387236a40fa374880002f4`** 出现在 `/anti_logs`、`/ra` 等路径上
- **mIS 每次注册都不同**，同设备差异 ≈ 跨设备差异
- **不存在固定逐位 key**（pos 5/8 可行 delta 为 0）

**推断：**
- mIS 极可能是**服务端签发/映射的会话标识**，而非本地可算量
- 若是这样，则「纯靠设备指纹离线算出 mIS」这条路**不通**，
  用户方案只能走**「抓一次 → 永久复用」**（mIS 已证随注册变化，
  但**同一份 mIS 是否可反复用于取同一个 DUID** 尚未验证 —— 这是新的关键实验）
