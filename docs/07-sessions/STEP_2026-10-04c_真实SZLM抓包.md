## 五、★ 解密尝试结果（全部失败，但要如实记录）

### 5.1 mIS 性质 —— **旧假设被否证**

用 6 个 mIS 样本做差分（`mis_key_test.py` / `mis_sparsity.py`）：

```
① XTQ_Watch【同一设备】两次注册的 mIS 完全不同（36/36 字节都不同）
② 汉明距离：
     同设备两两 : 111 / 132 / 155 位（38% / 46% / 54%）
     跨设备平均 : 118 位（41%）      随机基线 144 位（50%）
   ⇒ 同设备差异 ≈ 跨设备差异
③ ★ 逐位求「能让该位置所有样本都落回 base64url 的 delta」：
     pos 5 = 0 个，pos 8 = 0 个
   ⇒ 【不存在任何固定逐位 key】
   ⇒ 「mIS = XOR(base64(27字节), 固定key)」【不成立】
```

**⇒ `GOAL_GAP_CLOSURE_AUDIT.md` 缺口 A 的前提（只差 36 字节 key）需要修正。**

### 5.2 池常量 XOR —— 失败

```
试过：0x109CF0 / 0x10924C / 0x1090F8 / 0x0FEC5C / 0x110DC8 / 0x0E115C / 0x1783E4
      × 2 种字节序 × 24 个偏移 × 5 种后处理（无/zlib/gzip/deflate-raw/b64+zlib）
结果：无有效明文
```

**★ 关键否证**：对 56 字节响应，**不存在 4 字节周期 key 能让位置 0/1/2 变成可打印字符**
（`k[0]`、`k[1]`、`k[2]` 的可行值集合都是空集）。
⇒ **响应不是「文本 XOR 池常量」**。

### 5.3 AES —— 失败

```
试过 14 个密钥（CRYPTO_ITEMS.md 全部 + h 的 4 种形态 + p + 包名 + shuzilm + suffix）
      × 5 个偏移（0/4/8/12/16）× 5 种后处理
结果：无有效明文
```

**★ 注意响应的 `Content-Type: application/octet-stream`**（请求声称 `application/json`）——
说明**响应本身就是二进制**，不是被混淆的 JSON 文本。

## 六、推论（明确标注为推断）

```
1. 文档 §「body = zlib(JSON) XOR 周期池常量」可能只适用于 mdna 端点，
   adt/daa 两条线用的是【另一套加密】

2. h（16 字节）高度可疑是密钥或密钥派生源，但直接当 AES key 用不成立
   ⇒ 可能是 key = KDF(h) 或 h 参与别的构造

3. 56 字节响应的固定 18 字节头 + 可变体，更像【二进制协议帧】
   而不是「加密的 JSON」

4. mIS 每次注册都变、且无法用固定 key 还原
   ⇒ 更像【服务端签发的会话标识】而非本地可算量
```
