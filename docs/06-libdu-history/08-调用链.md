# ★★ 调用链打通：驱动 -> 解码 -> 属性名 -> 取值

> 日期：2026-10-03
> **本轮打通了 libdu.so 采集设备属性的完整前四段调用链，并定位了关键辅助函数。**

---

## 一、★★★ 已打通的调用链

```
① 驱动函数 0x07DBEC                       （采集设备属性，1536 条指令，42 次 bl）
        ↓ bl 13 次
② 属性解码器 0x0DA388 ~ 0x0DABC0          （每个解码一个属性名）
        ↓ 从 .rodata 解密
③ 属性名（'ro.microvirt.hmac' / 'persist.nox.wifimac' / 'sys.usb.vserialno' …）
        ↓ 存入 @0x162DD0 指向的对象，随即 ldr+blr
④ 取值回调                                 （按属性名分派，指针在 .bss）
        ↓
⑤ ??? -> 汇总 -> 编码 -> mIS               （待打通）
```

## 二、★ 关键函数清单（本轮新增）

| 地址 | 作用 | 判据 |
|---|---|---|
| **`0x1143BC`** | **取「属性名字符串常量」**（驱动里调 13 次） | 在 0x0DAF60 处被调后直接 `bl 0x152F80` |
| **`0x152F80`** | **`getprop` 的调用链** | 之后把返回值 `str` 进回调槽 |
| **`0x0DAF78`** | **注册回调**：`str x0,[0x162DC8]` | 见下方反汇编 |
| `0x13FE10` | 返回一个计数并与 `0x1c`(28) 比较 | `cmp w0, #0x1c` |
| `0x0DAFF8 / 0x0DB034` | 清理状态（`0x162DD8`、`0x162DC8` 置零） | |
| `0x0DB078` | 初始化入口：置 `0x162DD8 = 1`，调 `0x0DAEF8`、`0x114B54` | |
| `0x0DCBE8` | **`strdup`**（已识别） | `strlen`+`malloc`+`memcpy`+`strb 0` |

### 2.1 注册回调处的反汇编（0x0DAF58~0x0DAF78）

```asm
0DAF58  adrp  x8, #0x15a000
0DAF5C  ldr   x8, [x8, #0x780]        ; 取一个对象/字符串
0DAF60  and   x0, x8, #0xfffffffffffffffc   ; ★ 清低 2 位（去掉 tag）
0DAF64  bl    #0x1143bc               ; ★ 取属性名常量
0DAF68  mov   x1, x0
0DAF6C  mov   x0, x19
0DAF70  bl    #0x152f80               ; ★ 按名字取值（getprop 链）
0DAF74  adrp  x8, #0x162000
0DAF78  str   x0, [x8, #0xdc8]        ; ★ 结果存入回调槽
```

**⇒ 这就是「属性名 -> 取值 -> 存槽」的原子操作。
   同一模式在该区域重复 3 次（槽 0xDC8 / 0xDB0 / 0xDB8）。**

### 2.2 「清低 2 位」是重要线索

```
and x0, x8, #0xfffffffffffffffc
⇒ 这是【带 tag 的指针】—— 低 2 位存类型/标记。
   说明 SDK 内部用了带标记的引用计数对象（类似 JSValue / 变体类型）。
   ⇒ 那 13 个解码器返回的字符串，很可能也是这种 tag 形式。
```

## 四、★★ 下一步（最后一段：属性值 -> 汇总 -> mIS）

```
已知交汇点：
   · 驱动函数 0x07DBEC 有 720 字节栈（sub sp,#0x2d0）
   · 它在 0x07F0A0 之后连续调 0x1143BC（13 次）—— 疑似「逐个追加」
   · 属性值最终应当汇总到某个缓冲区，再被哈希/编码

⇒ 三种追法：

做法 A：反汇编 0x07F000 ~ 0x07F3EC（驱动函数尾部）
   · 看它把 13 个属性值怎么处理（拼接？逐个喂给哈希？）

做法 B：反汇编 0x114B54（在 0x0DB08C 处被调）
   · 它紧跟「置 0x162DD8=1」之后，像「启动采集」的入口

做法 C：反汇编 0x1143BC 的完整实现
   · 它被调 13 次，是「取属性名」的公共入口
   · 看它内部是否有【属性名 -> 索引】的映射表
```

**做法 C 最直接** —— 它可能就是「属性表」的访问器，
看它内部就能一次拿到全部属性名与顺序。

## 六、教训

```
① 「找不变量」比「找调用者」有效（重复验证）。
   解密函数没有 bl 调用者 —— 换方向找「谁批量调用」，
   在 779 个函数里精准命中 1 个驱动函数。

② 函数地址聚集是强信息。
   13 个解码器集中在 0x0DA388~0x0DABC0；
   紧接着 0x0DAF78~0x0DB0A0 就是「注册/取值」——
   编译期把相关代码放一起，这个规律可以直接用于定位。

③ 「清低 2 位」这类位运算要停下来看一眼。
   `and x0, x8, #0xfffffffffffffffc` 一眼看出是【带 tag 指针】，
   立刻知道了 SDK 的对象模型 —— 这比继续往下翻指令更有价值。
```
