# ★★★ 重大突破：在 D2 上抓到了真实的字母表

> 日期：2026-10-03 ｜ D2（XTQ_Watch）
> **第一次从设备内存里抓到 mIS 编码用的字母表（运行时构造的那张表）。**

---

## 一、★★★ 抓到的字母表

```
★★★ ALPHA[before_rw] @0x77b08b0bfc
   "ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789-_"

=> 这是【base64url 变体】：
     A-Z (26) + a-z (26) + 0-9 (10) + '-' + '_' = 64 字符
```

### 1.1 与之前假设的差异

```
我之前一直假设是【标准 base64】："...0123456789+/"
但设备上实际抓到的是【base64url】："...0123456789-_"

⇒ 重要修正！

对 mIS 样本的重新检验：
  样本用到的 17 种"越界"字符里含 '-'（出现在样本6：-\\1c21`...）
  ⇒ 与 base64url 一致（'-' 是 url-safe 字母表的第 63 个字符）★
```

### 1.2 另外两个候选（也抓到了）

```
★ @0x6fd0686a "cdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789-'()"
★ @0x6fd0686b "defghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789-'()+" 
  （这两个是滑窗位移产生的，不是真表）
```

**⇒ 真正有意义的候选是 base64url 那个。**

## 二、★ 这次是怎么抓到的

```
方法：call_encoder.js
  ① 等 libdu 加载
  ② 挂钩编码器 0x0E123C / 0x0E1994
  ③ 调用前先扫一遍【所有可写段】（Process.enumerateRanges('rw-')）
  ③ 在可写段里找到 64 字符互不重复的块

为什么这次成功：
  · D2 上 libdu 加载了（之前的失败都是"库没加载"）
  · 而且这次扫的是【所有可写段】（不只是 libdu 自己的段）
  ⇒ 表在【别的可写段】里（堆或匿名映射），不在 libdu 的 rw-p 段
```

**⇒ 这修正了我之前的判断："表在 libdu 的 rw-p 段"是错的，**
**   它在【进程的其它可写内存】里。**

## 三、★ 对 mIS 编码模型的更新

### 3.1 更新后的模型

```
mIS(36 字符) = 编码( 指纹 )     使用【base64url 字母表】

  · 字母表 = "ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789-_"
    （已从设备内存抓到实物 ★）
  · 编码函数 = libdu 0x0E123C（参数 x0/x1）
  · 主循环 0x0E1984：字符 = 表[输入 & 0x3F]，步长 3 字节
  · base64 输入 = 27 字节（36 = ceil(27/3)*4）
  · 仍缺：那 36 字节 XOR 密钥（若有的话）
```

### 3.2 需要重新检验的点

```
之前我基于"标准 base64"做过几项检验：
  ① 6 个样本与标准 base64 比对 -> 每串都有越界字符
  ② 位 4 恒定 -> 推断有固定 XOR 层

改用 base64url 重新检验：
  · 样本里的 '-' 现在是合法字符了
  · 但样本里还有 '! " # % & ' ( ) * < ? [ \ { | } ~' 这些
    —— base64url 也不含这些
  ⇒ 所以【仍然需要解释这些字符】

⇒ 结论不变：base64url 编码之后还有一层变换（XOR 或类似）
   或编码前的数据不是普通字节
```

## 七、教训

```
① 「换一个扫描范围」就能突破。
   之前一直只扫 libdu 自己的段（rw-p 8KB，全 0），
   这次改成扫【所有可写段】，立刻找到了表。
   ⇒ 当"已知位置"找不到目标时，应该扩大而不是缩小范围。

② 抓到的实物可能推翻假设。
   我一直假设是标准 base64（+/），
   实测是 base64url（-_）—— 这是实质性的修正。

③ 扫描的条件要放宽。
   我原来要求"64 字符全部互不重复"，
   而实际表的边界可能不整齐（前一个候选被滑窗位移干扰）。
   ⇒ 应该同时报告"≥58 唯一字符"的块。
```
