## 二、★ 本轮的六个关键突破

### 2.1 ★★★ maps 重定向（替代危险的 read 钩子）

```
问题：Coolapk（网易易盾加固）读 /proc/self/maps 扫 frida-agent → 检测到注入 → 弹窗+退出
旧方案：挂钩 read() 过滤 maps 内容（anti_debug_v5.js 的做法）
        ⇒ read 是极高频函数，全 app 每次读都进 JS ⇒ 【酷安直接 ANR】
新方案：在 open/openat 层【重定向】——
        遇到 /proc/(self|<pid>)/maps|smaps 时，
        现场生成一份【滤掉 frida/gum/gadget 行】的副本到 app 私有目录，
        把副本的真实 fd 返回给调用方 ⇒ 完全不碰 read，零高频开销

实测：
  [ok] open（maps 重定向）
  [ok] openat（maps 重定向）
  ★★ 重定向 maps: /proc/self/maps -> fd=178
  ★★ 重定向 maps: /proc/27497/maps -> fd=79
⇒ 生效，且进程不再自杀、不再弹"该应用被注入so"
```

### 2.2 ★★★ 性能：无差别 hex 转换是 ANR 真因

```
现象：MODE=2（读参数）一开就 ANR，MODE=1（只计数）却没事
根因：push() 对【每条】SSL 记录都做 toHex(arr, 16384)
      4221 条 × 16384 字节 ≈ 7000 万次 JS 字符操作 ⇒ 拖死
修法：热路径只做轻量判断，只对有价值的记录做 hex
      · CIPHER 记录：保留，cap 32768（数量少）
      · SSL 记录：仅非全零才保留，cap 2048
⇒ 之后再没 ANR
```

### 2.3 ★★★ 安全点按（不再误跳浏览器）

```
问题：用【缓存的】按钮坐标点按 → 页面状态一变就点到《用户协议》链接 → 跳浏览器
修法：每次点按前【重新 dump UI】，确认「同意协议并继续」确实在场才点；不在就绝不点

实测：
  [  2s] prefs=6    协议页 点按#1 @(210,425) bounds=(118, 411, 302, 450)
  [ 21s] prefs=34   协议页 点按#2 @(210,425)
  [ 48s] prefs=289  非协议页（不点）
⇒ 全程没跳浏览器
```
