## 二、政策声明的采集清单

### 设备基本信息（必选）

```
设备制造商、设备型号、设备品牌、设备名称、设备系统版本、应用版本、
系统语言设置、输入法设置、时区、存储空间、屏幕分辨率、屏幕亮度、
CPU 信息、内存信息、电池状态
```

### 设备唯一标识符

| 系统 | 字段 | 必选 |
|---|---|---|
| iOS | IDFV、IDFA | 是（IDFA 可选） |
| Android/鸿蒙 | Android\ID、Boot\ID、OAID | 是 |
| Android/iOS | UAID | 否 |

### 硬件序列号与高敏感标识（默认不采集）

```
IMEI、IMSI、MEID、SN(设备序列号)、MAC地址、ICCID
处理方式：仅检测上述标识符在当前系统版本下的可获取性及格式合规性，
         不存储任何原始标识符值，仅记录检测结果的风险评分
```

### 网络信息（必选）

```
网络连接类型(WiFi/4G/5G)、运营商类型、网络状态信息、IP 地址、DNS、
代理信息、WiFi 信息(SSID、BSSID、网关)、蓝牙信息
```

### 基站位置信息（可选）

```
网络接入形式、MNC、MCC、LAC、CID
```

### 应用列表（默认关闭）

```
应用包名、应用名称、应用版本号、应用签名信息
处理方式：客户端本地不可逆加密后上传，服务端仅做哈希比对
```

### 传感器 / 环境特征 / 物理环境

```
传感器：光、磁场、重力、压力、方向、旋转矢量、陀螺仪、加速度、线性加速度
环境：模拟器检测、Root/越狱、USB 连接、Hook 框架、多开/分身
物理环境：屏幕亮度、温度（仅 Android）、电池状态、媒体文件 MD5、设备所在地区
```

## 三、2026-04-04 版删除了什么

| 条目 | 旧版（2026-04-03） | 新版（2026-04-04） |
|---|---|---|
| **GPS 坐标** | 「授权开启可获取的设备大地坐标」 | **删除** |
| **ACCESS_FINE_LOCATION** | 权限表里有 | **删除** |
| ACCESS_COARSE_LOCATION | 有 | 保留（标记可选） |
| IMEI/IMSI/MAC 处理方式 | 「辅助加强设备持久性识别」 | 改为「仅检测可获取性，不存储原始值」 |

| 运营商标识 UAID | 未单列 | 新增为独立字段 |

旧版原文（「设备物理环境信息」一行）：

```
……设备所处的温度（仅限安卓系统）、~~授权开启可获取的设备大地坐标、~~设备的
电池状态、媒体文件MD5值及设备所在地区（如中国与美国）。
```

**⇒ 政策方向是明确收紧的。**

## 四、实测与政策的落差

### 落差 1 🔴 GPS 坐标：政策已删，v9.0.1 仍在采

**实测**（酷安 v9.0.1，2026-10 抓，政策更新之后）：

```json
"G8U": { "MYA": "2869076,70640", "H4S": "25.474575,1.646057" }
```

`H4S` 解码 = `25.474575,1.646057` —— **纬度 25.47N、经度 1.65E，小数点后 6 位。**

**政策**：只写「设备所在地区（如中国与美国）」，没有「坐标」「经纬度」「大地坐标」任何字样。

**⇒ 政策承诺的粒度是国家级，实际采集是米级。**

**补充观察**：
- v8.4.0（旧版 SDK，知乎）的 `G8U` 是 `0.000000,0.000000`（未定位）
- v9.0.1（新版 SDK，酷安）的 `G8U` 有真实坐标

字段本身一直存在，是否有值取决于设备定位权限。单台设备不能断言「新版采得更多」。

### 落差 2 🔴 真实 MAC：政策说「不存储原始值」，v8.4.0 明文上报

**实测**（知乎 v8.4.0，`d2api.vB2`）：

```json
"LLS": "20:0E:3C:11:58:F7"
```

完整真实 MAC，明文，未编码、未哈希、未加盐。

**政策**：「MAC地址 …… 不存储任何原始标识符值，仅记录检测结果的风险评分」

**⇒ 报文里就是原始值本身。**

**✅ 但有一个正面发现**：v9.0.1（酷安）里已经没有真实 MAC，只剩伪 MAC：

```json
"P1J": "13A365:CCAF40:AD4AA9"    ← SHA1(ANDROID_ID) 的三段切片
"AYk": "13A365:CCAF40:AD4AA9"
```

**⇒ 新版本 SDK 确实执行了整改，政策修改和 SDK 修改在这条上对得上。**

### 落差 3 🟠 唯一标识符清单不完整

政策列举的只有：IDFV、IDFA、Android\ID、Boot\ID、OAID、UAID。

实测还有：

| 字段 | 内容 | 性质 |
|---|---|---|
| `6yY` | Widevine DRM deviceUniqueId | 硬件级不可重置 |
| `dJs` | eMMC CID `150100525831424d420751004057c400` | 闪存永久序列号 |
| `p1m` | eMMC 序列号 `0x51004057` | 硬件唯一 |

### 落差 4 🟠 一批字段政策里连名字都没出现

| 实测字段 | 内容 | 政策归类 |
|---|---|---|
| `Q23` | 系统 CA 证书列表 | ❌ 没有 |
| `52J` | 10 个系统路径的 `inode:dev` 列表 | ❌ 没有 |
| `Bos`/`IAI`/`IJK`/`aFw`/`KyU` | 5 组目录访问/修改时间戳 | ❌ 没有 |
| `YWu` | `/etc/hosts` 内容 | ❌ 没有 |
| `w91` | `/system/fonts` 文件名列表 MD5 | ❌ 没有 |
| `gEd` | `libreference-ril.so` / `libc.so` 的 MD5 | ❌ 没有 |
| `ne8` | `libdu.so` 自身 MD5 | ❌ 没有 |
| `zvW` | Canvas 指纹 MD5 | 🟡 只在小程序/Web 版提到 |
| `6yY` | Widevine deviceUniqueId | ❌ 没有 |
| `dJs` / `p1m` | eMMC CID / 序列号 | ❌ 没有 |
| `iYB.Zne` | 全部网卡地址（含公网 IPv6） | ✅ IP 地址 |
| `iYB.MCN` | 网关地址 | ✅ WiFi 网关 |
| `wSK` | 内网 IP | ✅ IP 地址 |
| `R68` | 疑似基站/小区 ID | ✅ 基站信息 |
| `Cl5` | APK 完整安装路径 | ✅ 应用安装 |

**特别说明**：`52J` + 5 组目录时间戳合起来基本等于「文件系统指纹」，
跨刷机、跨恢复出厂都可能保持不变 —— 唯一性远超一个「设备 ID SDK」所需。
但政策里连这些字段的名字都没有。

## 五、政策描述与实际实现的不一致

### ① 「删除去位的脱敏处理」—— 描述准确

**政策**：

> 从客户端收集到数据后，于客户端本地进行删除去位的脱敏处理，
> 确保数据无法关联识别，保证采集的安全。

**实测**：

```
foO = encode_543EC( ANDROID_ID 去掉第 (15 - P%10) 位 )
例：288daec08ec17639 → 去掉末位 → 288daec08ec1763 → 编码 → 14d7f8b2ed9f993
```

**⇒ 确实是「删除去位」，描述一致。**

⚠️ 但 16 位删 1 位后仍是 15 位，碰撞空间 `16^15`，
说「无法关联识别」在技术上站不住。

### ② 「Rijndael 改进的 256 位加密算法」—— 描述不准

**政策**：

> 对报文内容加密，我们采用基于 Rijndael 自主改进的 256 位的加密算法，
> 利用置换技术以及泛化技术，配合产品模块更新策略，实现针对不同版本的模块、
> 不同的客户采用不同的密钥。

**实测**（报文三层结构）：

```
第 1 层  明文 JSON
第 2 层  zlib deflate（标准库，魔数 78 9c）
第 3 层  XOR，body[i] = comp[i] ^ key[i % 48]
         key 是硬编码在 libdu.so 里的 48 字符可打印 ASCII 串：
         "xp7j@&!v5]2k#+3z{n9$q^r%[8f1*d4e:c>0l?m/6)yb-=w}"
```

字段级混淆：

```
shift = (P % 100) % 57 + 1
case  = (P // 100) % 4
逐字符在 0x20–0x7E 的 95 字符环上移位 + 四种位置置换
P 来自报文里 2cO 字段的末 3 位 —— 报文自带的明文值
```

AES 用在哪：**只用于本地落盘**，`device_id = base64(md5(sid[:64]) + sid)`，与传输无关。

**⇒「Rijndael 256 位」更像描述落盘加密。传输层的真实强度是 XOR。**

「针对不同版本采用不同密钥」这点部分成立（v8.4.0 和 v9.0.1 的 XOR 密钥确实不同），
但**同一版本内所有设备共用一把**。

### ③ 「SDK 不驻留、数秒后自动退出」—— 存疑

**政策**：

> SDK 模块启动并迅速完成对授权信息的收集工作，收集完成后便会自动关闭退出，
> 不进行后台自启动和关联启动。整个过程一般持续数秒。

**旁证**：

- so 里有 **11 个上报端点**（dai/daa/ldc/dcc2/adt/d2api/tra_file/aads/audd-valid/audd-token/mdna）
- 反编译可见心跳守护与 rtnetlink 监听逻辑
- `UOv` 字段记录「开机时刻」，说明 SDK 关心设备运行时长

**⇒ 与「数秒后完全退出」的表述存在张力，但心跳/监听是否属于可信ID模块需要更严格的隔离验证。**

### ④ 「不收集用户行为信息及用户隐私敏感信息」

**实测**：

- `Q23` 收集系统 CA 证书列表 → 能直接看出用户装过抓包工具
- `52J` + 目录时间戳 → 能推断设备首次开机时间、系统使用历史
- `G8U` 精确位置

**⇒ 从技术角度看，这些构成很强的设备画像，不只是「设备基本信息」。**

## 六、合规观察

### ① 告知义务已明确转嫁给 App 方（2026-04-04 新增）

政策要求 App 开发者：

- (a) 在 App 隐私政策中明确披露 SDK 名称、提供方、信息类型及处理目的
- (b) 首次启动或首次调用前，通过弹窗单独告知并取得明示同意
- (c) 用户拒绝授权后，App 核心功能仍须可用

并承诺「在合作协议中将上述义务作为强制性条款」。

**⇒ 用户能不能看到这份清单，取决于 App 方有没有如实披露。**

### ② 「只检测不存储」的承诺可验证性低

政策说 IMEI/IMSI/MEID/SN/MAC/ICCID「仅检测可获取性，不存储任何原始标识符值」。

但 v8.4.0 实测报文里 `LLS` 就是明文 MAC —— 旧版本并未执行这条。
新版本 v9.0.1 已整改，但时间点晚于承诺。

### ③ 字段清单与实际采集面差距明显

政策列举的字段约 40 项，而：
- v8.4.0 的 `d2api` 报文有 **144** 个指纹键
- v9.0.1 的 `mdna` 有 **79** 个键

即便考虑字段名混淆导致的重复计数，实际采集面仍显著宽于政策描述。

### ④ 跨境传输已披露

启用海外节点时，向阿里云新加坡（ap-southeast-1）、德国法兰克福（eu-central-1）、
美国弗吉尼亚（us-east-1）传输「去标识化后的设备风险评分字符串（示例：riskScore:42）」。
未启用则仅存中国境内。

## 八、说明

1. 本文「实测」结论均来自自有测试设备的抓包与解密，样本为酷安 v9.0.1 与知乎 v8.4.0，不代表全部设备与版本。
2. 「政策承诺」直接引自官方隐私政策 2026-04-04 版原文（via termshub.cn 镜像，官网为 JS 渲染无法直接抓取）。如有版本更新，以官网为准。
3. 设备数量、Android 版本、是否授权定位等因素都会影响某个字段是否有值。
